# Gorilla Grip Trainer design

## Purpose and ownership

Gorilla Grip Trainer is a standalone Openplanet plugin for practicing icy-tire jumps. It rates **when the physics engine commits the intended slide direction before the last wheel leaves**, confirms the result on landing, and records attempts for review. Its source belongs in `Teuflum/Gorilla-Grip-Trainer`. The separate `tm-gorilla-grip-reverse-engineering` repository remains the source for the physics report and controlled evidence; the old Gorilla Grip Rater source and design documents have been removed from its current tree.

The plugin is a trainer, not a speedometer or a claim that one multiplier alone determines acceleration. It reads game memory but never writes it. Build-specific exact reads must pass the existing executable and active-car checks. An unsupported build shows an amber Openplanet warning that the offsets need manual review, then unloads before trainer initialization. An uncertain contact sample shows `UNRATED` with a reason; it must never advertise a frame-perfect grade from an estimate.

## Player experience

| Moment | Display | Audio |
| --- | --- | --- |
| 100 ms of continuous airtime after a recent pre-takeoff reversal | One Grade widget shows a small, calm `S+`–`D` preview only when the physics mode switched; otherwise it stays empty | Local `SP2_SND_GROUP_00000006.wav` cue when a recent grounded input reversal was observed |
| During the rest of airtime | Preview remains; diagnostics show direction-mode age/readiness | No announcer |
| At least 80 ms after first landing contact, once tire force is active | The same Grade widget expands into a large animated final S+–D or `MISSED`; the popup uses the selected style (see 2026-09-27-grade-popup-pictures-design.md), with an optional picture per result; only S and S+ pictures bounce; an ordinary same-direction landing stays silent | Success: one random clip from the grade's enabled landing voice list. Miss: local `SP2_SND_GROUP_00000002.wav`, with no success call |
| Confirmed map finish | Optional finish summary; run enters history as `FINISHED` | Local `WSR_Wakeboarding_Results.mp3` starts and loops while the finished run remains active |
| Restart or map exit after at least one rated jump | Attempt enters history as `RESET`; active score and combo reset | Stop finish music; no finish summary |

A 100 ms minimum flight suppresses tiny bounces. The takeoff cue is delayed until that minimum has passed, so it still feels attached to takeoff without playing for an unrated hop or a routine continuation of the same slide. The announcer speaks only on confirmed landing, avoiding two spoken clips close together. Each grade's list has independently editable filenames and gains; when more than one clip is loaded, select randomly without repeating the immediately previous choice. The visual result must appear when the verdict is ready, independent of audio duration.

## Timing and success rules

The exact source is the active physics vehicle's smoothed steering (`vehicle+0x1430`), stored direction (`+0x14e5`), mode-change game timestamp (`+0x14d8`), stored force multiplier (`+0x14dc`), and force gate state (`+0x1600`) on the tested build. The vehicle-model recovery delay is `400 ms` in the tested build. The plugin also samples all four wheel-contact flags and their icing values. Average takeoff icing of at least `0.65` and speed of at least `50 km/h` make a jump eligible by default; these are configurable *rating filters*, not universal slide thresholds. With event logging on, a stored-direction switch or late steering reversal that these filters (or the minimum flight) drop leaves a debug line naming each failed filter and the value it saw, so the limits can be checked against real jumps. The surface material is not itself an eligibility filter, so icy tires can be evaluated on non-ice takeoff material.

**Takeoff gate:** Observe a nonzero stored slide direction while grounded. Track the prior stored mode, raw steering sign, and exact mode-change timestamp through the last contact interval. A timing preview exists only when a *new opposite stored mode* commits while any wheel still touches, within `250 ms` before last-wheel departure. Raw steering reversal can be used to recognize an attempted setup and play the jump cue, but raw input alone never earns a timing grade. A routine jump that keeps the same stored and landing direction shows no preview and no rating, even if full grip carries through the landing. If the contact clock at takeoff is inconsistent with the frames around it, the attempt is `UNRATED`, not a guessed grade.

At first all-wheel airtime, freeze the pre-takeoff mode and the latest exact mode-change timestamp. The takeoff tick is the car's contact clock (`vehicle + 0x1414`): the physics step updates it on every tick that processes wheel contact, so it stops at the first tick whose previous contact flags were all clear, and sub-tick wheel grazes do not move it. It must lie after the previous frame's physics clock and at or before the current one. The lead is `takeoffTick − modeAt`, one exact number on the physics clock (`vehicle + 0x4f4`); the frame clock runs up to 9 ms ahead of it and is used only to convert ticks to race time. A mode can switch on the takeoff tick itself: the controlled +13 run recorded left mode with one wheel at game clock `6,771,501 ms`, then right mode and all-air at `6,771,512 ms`, with the exact switch timestamp `6,771,510 ms`, a 0 ms lead (S+). Require a previous opposite grounded mode. The per-wheel timestamps at `vehicle + 0x1820 + 0xb8·i` also date sub-tick grazes and are used only for the landing. Details and measurements: [tick-exact timing](2026-09-27-tick-exact-timing-design.md).

For a preview, accept a mode switch only if it changes from the old nonzero mode to the opposite mode **while a wheel still touches**. Use these default timing regions after calibration. The grade depends only on switch timing, never on how close the force field is to `2.0x`:

| Physics switch lead before last-wheel departure | Preview and successful final grade | Base points |
| --- | --- | ---: |
| Confirmed 0 ms lead | S+ | 150 |
| Other confirmed intervals within 0–15 ms | S | 150 |
| >15–35 ms | A | 120 |
| >35–65 ms | B | 90 |
| >65–110 ms | C | 60 |
| >110–250 ms | D | 30 |

If there is no committed opposite mode before takeoff, leave the preview empty. A direction stored more than `250 ms` before takeoff cannot earn D merely because it remains stored. S+ requires a 0 ms lead, with no user setting; it uses S points and its S voice pool. Other S intervals represent the final contact opportunity within the validated interval. `UNRATED` remains possible when the exact physics read disappears, contact timing is lost, or the force check never becomes eligible; timing comes from the physics timestamps, not from display frames.

The landing tick is the earliest timestamp among the grounded wheels that is newer than both the takeoff and the last all-air frame; a wheel whose contact flag is set but not yet processed still carries its previous timestamp, possibly a graze from the flight, and counts from the next tick. A touch the game processed between two all-air frames moves the car's contact clock: it counts as a brief touch before the landing, and if that landing is not rated the flight starts again from it. Force becomes eligible once a front wheel touches (its contact cannot start before the landing), the mode age has reached the model recovery delay, and the backwards-motion gate (`+0x1600`) reads clear; the gate has no timestamp, so eligibility restarts at a frame that shows it set. The verdict is decided at the check tick, the later of landing + `80 ms` and eligibility + `30 ms`, using the stored state as of that tick: a switch whose `modeAt` is after it is ignored, and a lapse to neutral (which stores `modeAt = 0xFFFFFFFF`) is dated from the neutral spell's start (`vehicle + 0x14e0`) plus the model's neutral timeout. Abandon the pending verdict (`UNRATED`) if force is not eligible within `1000 ms` of the later of touchdown and the end of the recovery delay. A short bounce does not start a new flight while this verdict is pending. Confirm a previewed S–D result only if the stored direction held through the check tick, the mode age at eligibility reached the recovery delay, and average landing icing is at least `0.34`, about what still starts an ice slide. The configured minimum icing applies only at takeoff, because tires lose icing in the air (a 2.75 s flight took them from 100% to 54%). Tire force does not decide: every multiplier reset writes `modeAt` in the decompiled car update, so a low multiplier without a reset means a low target (light steering, low speed), not a delayed grip; a debug line ("force did not rise although the direction held") records such landings when a front wheel has been down since eligibility, since a front wheel that bounces after the delay ends ramps the force only once it is back. A landing with neutral steering that then steers the matching way is therefore confirmed, since the stored direction held. If a previewed jump fails this confirmation, final result is `MISSED` with a reason. If there was **no preview**, classify `MISSED` only when an eligible icy-tire landing stored the opposite direction between takeoff and the check tick and the multiplier is still near `1.00x`. This includes a setup that was attempted too late or not attempted before takeoff. Otherwise the landing is an ordinary continuation and produces no result. If the exact read disappears or contact timing is inconsistent, use `UNRATED` without changing score or combo.

Only confirmed S–D results earn points or extend the combo. A confirmed `MISSED` after a delayed opposite-direction landing gives zero points and breaks the combo, whether or not a takeoff preview appeared. Without a preview, the landing is opposite when the stored mode switched away from the takeoff mode by the check tick: a neutral landing followed by steering the other way switches the mode on the ground and delays the force. A switch stored within `30 ms` of touchdown is named an opposite landing. If a late grounded reversal played the takeoff cue, the miss reason gives its lead before takeoff. An ordinary same-direction jump changes no score or combo. Award `base points × min(combo, 8)`. Spins are not counted or scored: they say nothing about the grip, and counting them from the car's heading proved unreliable. The preview never changes score. Preserve the existing per-run best combo and previous-run summary semantics.

During airtime, diagnostics show elapsed time since a valid committed mode change. Neutral mode and the game's `0xFFFFFFFF` unset timestamp show no mode timer, rather than a large age. The game code holds force for the model delay (`400 ms` on this build), permits incremental recovery until `2 × delay` (`800 ms`), then uses the target on the next eligible tire-force update. The measured grounded landing reached `2.0x` around 600 ms because force was being updated there; that measurement does not establish full force at 600 ms during a flight, when the stored force can remain stale. The widget labels 800 ms as the maximum window elapsed and checks actual force on contact. This upper limit is also the trainer's conservative landing-grade age requirement.

## Modular display and editing

One shared state machine feeds these independently placed widgets: (1) compact diagnostics containing steering, ±10% gate, direction, icing, and timer/force; (2) a Grade widget that shows the small provisional takeoff grade and then the large confirmed landing result in the same position; (3) combo; (4) score; (5) best combo; and (6) last run. A failed landing can turn a provisional S–D into `MISSED`; the timing grade itself never changes otherwise. A separate finish-summary panel appears only after a true finish. The optional Run History is an Openplanet window, not a gameplay widget.

The `Layout` settings tab uses the interaction pattern of Dashboard: each enabled widget receives a visible edit outline, title, drag handle, and resize corner while the tab is open. The Grade widget displays sample content there so it can be placed without replaying a jump. During play, NanoVG draws the widgets without hit boxes or mouse capture. Save each widget's normalized screen position, independent width/height or scale, and visibility. The combined Grade widget inherits the prior landing-result position to preserve existing layouts. Clamp restored positions to the visible screen after resolution changes. Provide per-widget reset plus reset-all, and separate show/hide settings. Layout stays flat and scrollable; Sounds uses compact collapsible categories. Rating controls remain separate; Sounds owns all audio controls. The default layout puts diagnostics low and central, the Grade widget near screen center, and scoring widgets near the sides; users can move every unit.

## Run history and finish summary

Store up to the newest `500` attempts in a local versioned JSON file in Openplanet plugin storage. No history is uploaded or checked into Git. A run contains map UID/name, local start timestamp, status (`FINISHED` or `RESET`), finish race time when present, final score, best combo, and an ordered jump list. Each jump records takeoff and landing race times, direction-switch lead in milliseconds (older entries may hold a range and a conservative-timing flag), preview grade, final verdict and reason, and combo and score after landing. Older entries may also hold a `spins` count, which is ignored. Save an attempt when it ends if it has at least one verdict, including `UNRATED` after a lost physics read or uncertain force contact. A restart, map change, or leaving play closes an unfinished attempt as `RESET` exactly once.

The optional Run History window starts closed. It uses compact attempt and jump tables, with timing, preview, score, and reason details shown for the selected jump. It filters by map and status. One icon-labeled Gorilla Grip Trainer submenu in Plugins opens history, toggles all widgets through the Display setting, and shows the finish summary when available. The window can be resized and closed without affecting play. A clear-history command requires an in-window confirmation and changes only local trainer data.

The finish summary appears once when the local player's game state enters a confirmed finish state, never merely because the race clock resets. It shows map name, finish time, final score, best combo, separate colored S+/S/A/B/C/D counts, MISSED/UNRATED counts, and best and median successful switch lead. It can be dismissed and has a setting to disable automatic appearance. It stays available until dismissed, restart, or map change. The 30-second local results track starts only for this true-finish transition, loops while the finished run remains active, has its own volume setting, and stops when a new run begins, the map changes, or its audio category is disabled. A master volume slider scales every cue immediately. Reopening history must not replay the track. Every configured clip, including results music, has a one-shot Play button; Stop preview stops that preview without affecting a real finish.

## Audio assets and local-only boundary

All user-supplied WAV/MP3 files are local test assets. The public repository contains source, asset-name documentation, and tests, with no game audio or landing impact bundled. A local install step copies any selected WAV/OGG/MP3 files from a user-selected source folder to the Trainer's Openplanet storage folder. The Sounds tab can open that folder through Openplanet's `OpenExplorerPath` API and offers an in-app picker listing its compatible files. Missing files disable only their own cue; the plugin remains usable and logs a clear load warning. Sounds owns all audio controls; there is no duplicate Audio tab. Master, takeoff, failure, grade voices, each grade pool, and finish music have independent enable switches. Every fixed cue and grade-list item has a filename, volume, and preview control in a compact row inside a collapsible category.

| Cue | Grade or timing | Default local file (volume) |
| --- | --- | --- |
| Jump cue | All eligible reversal-attempt takeoffs | `SP2_SND_GROUP_00000006.wav` (0.35) |
| Failed landing | MISSED only | `SP2_SND_GROUP_00000002.wav` (0.35) |
| Default S voice list | `Incredible`, `Great Air` | `Sample_0064.wav`, `Sample_0061.wav` (0.40 each) |
| Default A voice list | `Amazing` | `Sample_0065.wav` (0.40) |
| Default B voice list | `Excellent` | `Sample_0063.wav` (0.40) |
| Default C voice list | `Nice` | `Sample_0058.wav` (0.40) |
| Default D voice list | `Good` | `Sample_0053.wav` (0.40) |
| Results | Confirmed finish only | `WSR_Wakeboarding_Results.mp3` (0.25) |

The master volume defaults to 0.50. On a fresh install each default list keeps only the files already in LocalSounds, so missing clips do not show up as errors; the Sounds tab's **Reset to default** (confirmed with a second click, like every reset) restores the full default lists. A voice may be added to any grade list; the old airborne clips remain optional local files but are never played in air. All supplied announcer WAVs are mono 16-bit at 22,050 Hz. The result track is approximately 30 seconds. Do not copy or redistribute Nintendo game extracts in either Git repository.

## Architecture and verification

Use the installed single-file Rater and its source in the research repository's Git history as a reference while building a read-only physics sampler, transition/rating state machine, run-history store, audio director, widget layout/renderers, and history/finish windows. The entry point wires them together; presentation never determines the grade. Keep VehicleState as the only plugin dependency. Use Dashboard's public widget interaction as a reference for edit mode, but do not require Dashboard at runtime.

Verify against the known +13 instant and +12 delayed TICK variants, a stable same-direction slide jump (which must be ignored), the first 6.2 s landing, a deliberate post-contact steering reversal, short hops, and an unsupported executable signature. Also verify a true finish versus a reset, looped finish music, one-shot previews for each cue, history persistence across plugin reload, on-screen widget placement at the user's resolution and a second resolution, and local-only asset handling. Publish the Trainer code only after these checks. Keep the installed Rater until Trainer verification is complete, then disable/remove it locally so only one HUD runs.
